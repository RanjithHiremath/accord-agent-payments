THE PROTOCOL

A small agreement.
A complete exchange.

Think of a signed quote as a purchase order that software can check. It names the buyer, seller, price, network, expiry, and exact work.

01 /

Ask for the work.

A buyer sends a specific request directly to a seller. In this prototype, the service calculates a summary of a list of numbers.

02 /

Agree to the terms.

The seller signs its offer. The buyer checks the signature and its spending limit, including the network’s transaction fee.

03 /

Pay. Then receive.

The payment contract records the exchange once. The seller checks that record before delivering the promised result.

↳ A receipt proves payment. It does not prove that arbitrary work is good, or guarantee that a seller will deliver.

INDEPENDENCE BY DESIGN

The rules belong
between the agents.

The long-term goal is simple: participants can keep trading even if the people who built Accord stop running it.

That takes participant-operated software and a shared payment network. The protocol still runs on computers; independence means there is no mandatory company server in the exchange.

This first version runs on one computer. It demonstrates the exchange mechanics. Independent operators, public-network deployment, and interoperability still need testing.

RESEARCHED

Bitcoin / Lightning

Bitcoin payments can fit direct agent exchange. Lightning adds faster payments through funded connections called channels, which require liquidity and reliable operation.
